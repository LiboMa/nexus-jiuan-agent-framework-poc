# 规划方法与示例

## 一项任务的完整节奏

```
探测 → 理解与澄清 → 盘点可复用资源 → 出方案 → 用户确认 → 执行并轮询 → 验证 → 交付
```

1. **探测**（只读）：`whoami` 确认身份与档位；`caps` 看有哪些模块；`module <id>` 读相关模块的指南与配方。
2. **理解与澄清**：把目标改写成「做完后用户能看到什么、能用来做什么」。只问会影响方案的问题（例如数据从哪里来、给谁用、要不要对外分享）。
3. **盘点**：用只读的 `call GET` 列出已有的 Agent、工具、技能、数据连接、模板。能复用就复用。
4. **出方案**：每一步写清楚

   | 步骤 | 模块 / 操作 | 风险 | 预计耗时 | 怎么撤销 |
   |---|---|---|---|---|
   | 1 | `<模块>`：`<METHOD> <路径模板>` | read / write / destructive | … | … |

   另外说明可能消耗的模型额度、需要用户提供的东西（例如第三方密钥要用户自己在网页上填）。
5. **确认**：用户确认整体方案后，写操作逐个执行；遇到 `destructive` / `high` 的步骤，到那一步再单独确认一次。
6. **执行并轮询**：发起后台任务后用 `wait` 跟进；与平台上的 Agent 对话用 `chat`。
7. **验证**：只读地查一遍结果（状态、内容、能否正常对话），必要时用 `chat` 让新建的 Agent 试答一个问题。
8. **交付**：结果在哪里（网页路径，来自模块的 `ui_route`）、怎么改、怎么撤销、还有哪些没做。

## 规划原则

- **复用 > 组合 > 新建**：已有的 Agent / 工具 / 模板能满足就不新建。
- **可逆 > 不可逆**：能停用就不删除；能新建草稿就不覆盖原件。
- **先草稿，后发布**：发布、分享、对外开放放在最后，并单独确认。
- **先只读，后修改**：不确定接口会做什么，先 `describe`、`--dry-run`。
- **小步前进**：每一步验证通过再做下一步；失败了先看原因（错误码、`describe`），不要原样重试写操作。
- **如实说明限制**：`--include-denied` 里的原因原样转述给用户，由用户决定是否调整权限。

## 示例对话一：查询类（只读）

> 用户：帮我看看我在 Nexus 上有哪些 Agent，最近哪个用得最多。

1. `caps` → 找到与 Agent、统计相关的模块；`module <id>` 看操作。
2. `call GET <列出 Agent 的路径>`；`call GET <统计路径> -q <参数>=…`（路径来自 `module` / `ops`）。
3. 汇总成表格回答；不需要任何确认，因为全部是 `read`。

## 示例对话二：构建类（写操作 + 长任务）

> 用户：在 Nexus 上帮我建一个能分析销售 Excel 的 Agent。

1. 探测：`module` 读构建相关模块的配方（通常是「提交需求 → 轮询构建状态 → 验证」）。
2. 澄清：数据格式、输出形式、谁会用、是否已有相似的 Agent（先 `call GET` 列出来看）。
3. 方案：
   - 第 1 步 提交构建（write，几秒）——可以在网页上停止；
   - 第 2 步 等待构建完成（read，通常十几分钟，用 `wait`）；
   - 第 3 步 试用（`chat` 发一条测试问题）；
   - 预计消耗：一次构建的模型额度；撤销：在网页上删除这个 Agent（需要用户本人确认）。
4. 用户说「可以」→ `call POST <提交路径> --data '…'`（先不带 `--yes`，CLI 打印将要执行的请求，退出码 9）
   → 给用户看 → 用户同意 → 同一条命令加 `--yes` 执行。
5. `wait <状态路径> -p <参数>=<任务 id> --field data.status --until completed,failed --interval 15`。
6. `chat --agent-id <新 Agent id> --message "用这份样例数据试一下：…"`，确认回答合理。
7. 交付：网页位置、怎么继续调整（再次对话 / 更新工作流）、怎么删除。

## 示例对话三：高风险操作

> 用户：把那个旧的测试 Agent 删掉。

1. 先 `call GET` 找到它，向用户复述名称、创建时间、最近使用情况，确认是同一个。
2. 说明后果：删除后无法恢复（以平台为准，`describe` 的说明里会写），相关会话可能一并删除。
3. 用户单独确认后：`call DELETE <路径> -p <参数>=<id> --yes --confirm-destructive`。
4. 再 `call GET` 确认已不存在，告诉用户结果。

## 长任务的注意事项

- 第三方 Agent 的单次命令常有时间上限：`wait` / `chat` 用 `--timeout` 控制单次等待，超时（退出码 6）后再次 `wait` /
  `chat --attach` 接着等，平台上的任务不受影响。
- 凭证会自动续期，等几个小时也不需要重新连接。
- 不要用循环反复发起同一个写操作来「重试」：先查状态，确认上一次没有生效再说。
