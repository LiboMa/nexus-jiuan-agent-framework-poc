一图看懂

九安平台上，业务流程、财务、知识库各类 Agent 都走同一条路：九安的 Agent 任务服务套上同一个信封，经我们的 A2A 适配层送到 Nexus 上对应的 Agent；结果回来，各自去该去的地方。新增一类 Agent，这条路不用改。

核心结论

  • 一套通用层，所有 Agent 共用。信封、发现、调用、状态、错误码、Agent 接入、路由、Agent 任务服务，对每类 Agent 都一样。通用层不认识任何具体任务。
  • 每类 Agent 一份任务契约。新增一类 Agent，只加任务契约和九安里这个任务的组装器与展示，通用层不动。
  • 九安里只有一个文件知道 A2A。我们交付 providers/nexus-a2a.mjs，挂在九安留给接入方的模型接入口下面，只加一个通用方法 agentTask；调用照常经过九安的统一调用中间件，暂停开关、额度、并发、时限、调用日志都是现成的。
  • 业务归九安，Agent 只干活。流程状态、留痕、人工复核都在九安里。Agent 不碰汇联易，不存九安的状态，不做最终决定，不改九安的数据。
  • 第一个任务是单据初审。每条规则和整张单据都回 通过 或 不通过，原因写在备注里；不论哪种，最后都由人复核。

分界：谁做什么

中间那条琥珀色的缝就是契约：信封加上任务契约。每一方只依赖它，不依赖对方的内部；改动只要不碰契约，就不用通知对方。

Nexus 平台给的和不给的（v0.3.28）

  • A2A：message/stream、tasks/get、tasks/cancel
  • 接受结构化的 DataPart（转成 JSON 文字交给模型）；可以带文件
  • 同一个会话编号就是同一段对话（多轮对话靠它）
  • 调用密钥 nxa_…，每把只对一个发布有效；每把每分钟 60 次；每个发布同时 8 轮；一次输入最多 10 万字

  • 不去重：重发就是新的一轮，会再计费；任务只留 24 小时，Nexus 重启就丢

九安收到结果后的两层检查

  1. 信封检查，所有任务一样：回答不超过上限、只有一个 JSON 对象；符合结果信封的格式；任务名、版本和请求一致，requestId 等于请求里的
  2. 任务检查：output 符合这个任务的输出格式，再做任务契约里列出的一致性检查；检查代码和任务契约一起交付

任何一层不过，就在同一个会话里要求 Agent 修正一次；还不过，这次调用算失败（AI_INVALID_RESPONSE）。

第一个任务：单据初审

first_review@1，业务流程类，一问一答，针对一张单据。输入是单据、对这张单据有效的已发布规则（带原文和引擎结论）、原件摘录；输出是综合结论和每条规则的结论与备注。

情况结论备注写什么
规则满足通过依据：哪个字段、哪份原件第几页、引用的原文
规则和这张单据无关（例如单据里没有住宿）通过「不适用：单据里没有住宿」
规则不满足不通过哪里不符合
缺材料，或拿不准不通过缺什么、哪里拿不准，宁可让人多看一眼
字段核对类，引擎已判和引擎一致可以解释，不能改结论
整张单据有一条不通过就不通过不通过时写清原因和要补什么

任务检查有三条：每条规则都有、且只有一条结果；字段核对类和引擎一致；有一条不通过，综合就不通过。公司、单据类型、生效期这类硬条件由九安代码先筛，Agent 只判断规则和单据内容的关系；票据真伪已在上游验证，Agent 不判断。

AI 步骤与审批流

九安里每次调用 Agent 都是一个 AI 步骤，状态对所有任务一样：进行中、完成、失败（可重试的自动重试一次）、拒绝（转人工）、作废（对象变了）、依据已更新（由人决定重跑）。审批流是第一个用到它的业务流程，点一个状态看细节。

状态怎么上报

Nexus 不推送结果。调用本身成没成看 A2A 任务状态；业务结论在 output 里。下表对所有任务都一样。

新增一类 Agent

以财务类的「费用分析」为例，要做的只有这些；通用层（补丁 0001–0003）不改。

  1. 任务契约：复制 contract/tasks/_template/v1/，填 task.json（家族 finance、对象 period、长任务 deferred: true、检查、作废条件、数据类别），写输入输出格式、检查代码和例子；在 tasks/index.json 登记一行。
  2. Agent：在 Nexus 上建好、发布；名片描述写「契约：jiuan.agent/v1」和「任务：expense_analysis@1」，固定版本。

  4. 九安的任务层：写这个任务的组装器（九安数据 → input）和展示（output → 报告页），登记一张平台卡片（额度、暂停、调用日志），路由表加一行。
  5. 测试：契约例子过检查；Agent 用例子各调一次；端到端测试；项目负责人确认后再提交。

  1. 系统身份：业务流程类要以 system:pipeline 读单据、跑预审和 AI 步骤；九安现在只允许 admin、analyst 的真人账号，要加一条受限的服务身份路径（安全相关）。
