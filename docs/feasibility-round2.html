第二轮可行性评估九安自助审核平台 × Nexus-AI v0.3.28

对象九安自助审核平台，测试环境开发包 v0.5.3（Node.js 24 + MySQL 8）日期2026-10-14
平台Nexus-AI 0.3.28 enterprise（nxs-beine1013）轮次第二轮；第一轮基于 v0.3.27
依据nexus-ai-operator 能力发现（33 个模块）与只读调用；v0.3.27 → v0.3.28 代码比对（232 个提交）；CloudFront、ALB、安全组、沙箱节点只读核查；审核平台 providers/ai-model.mjs 接入契约。除登录时按规则自动生成的一把 API 密钥外，没有在平台上创建任何资源

v0.3.28 没有让「整体迁入」变得可行，但让「对接」更顺了。平台照原样独立部署，providers/ai-model.mjs 经 A2A 调用 Nexus 上发布的 Agent。

三条路线的预审结果

按审核平台审单据的方式：先过规则核验，再给两档结论，每条结论都能追溯到依据。

路线 A

整体迁入 Nexus，1:1 复刻

  1. ✕访客身份与权限仍只有共享口令；访客以所有者身份运行
  2. ✕应用自己的数据库仍只有每个链接 256 KB 的存储
  3. ✕不经大模型的确定性执行页面仍只能执行 Agent 步骤
  4. ✕可靠的调度与数据管道仍不重试、不告警，没有入站 webhook
  5. ✕Node.js 24 运行时VM 里仍是 Node 18
审核意见

五个硬阻塞在 v0.3.28 一个都没有变化。

结论
不建议通过

依据：第 3 节

路线 C（推荐）

平台独立部署，Nexus 做 AI 层

  1. ✓原有行为全部保留平台照原样部署，只实现一个接入文件
  2. ✓对接通道A2A 对外发布，v0.3.28 新增
  3. ✓长调用流式返回，避开 60 秒源站超时

约 5.5–9 人日。客户接受留存期、环境加固完成后可以上线。

4推荐方案：平台独立部署，经 A2A 调用 Nexus

审核平台只改 providers/ai-model.mjs；调用方、中间件、页面文案都不动。点「演示一次调用」看一次请求经过哪些环节、各自有什么限制；切到「按新模板加固后」看两处限制如何解除。

  1. 审核平台单据详情页「AI 建议」
  2. 调用中间件超时 120 秒，并发 2，每天 150 次
  3. ai-model.mjsA2A 流式客户端，错误码映射，取消
  4. CloudFront源站读超时 60 秒：用流式返回 !回源 http，明文 ✓回源 HTTPS
  5. ALB 没有 /a2a 规则，经前端服务转发 规则直达发布网关 !附件约 7 MB 上限 ✓附件合计 40 MB
  6. 发布网关 :8003每把密钥 60 次/分钟，每个发布并发 8，额度闸门
  7. 沙箱 VM 里的 Agent钉住版本与模型；冷启动几十秒到几分钟
  8. 模型按请求里的任务和 schema 只输出 JSON

为什么改用 A2A 对外发布

应用 Agent API
第一轮方案		A2A 对外发布
推荐		API 密钥 + invoke
设计用途应用的机器接口给其他系统调用给编码 Agent 和脚本用
成熟度稳定，两个版本之间无改动Experimental；网关单进程运行v0.3.28 新增
凭证每个应用 Agent 一把，只能本人在网页签发每个发布可签多把；可设到期（最长 365 天）、轮换（旧钥宽限 24 小时）、停用代表一个真人用户；要实现密钥兑换与轮换
返回内容{text, data}，按输出 schema 提示模型并解析只有文本，平台不强制 schema文本
长调用同步阻塞，经 CloudFront 超过 60 秒即失败流式返回，或提交后轮询同步阻塞，同样受 60 秒限制
限流所有者预算与应用配额；不受每 IP 每小时 30 个会话的限制每把密钥 60 次/分钟，每个发布并发 8；额度用尽自动暂停只有月度 token 额度
版本与模型跟随应用版本跟随最新或钉住某一版；可单独指定模型Agent 当前版本
内容留存会话以所有者身份保存，调用记录里有完整过程隐藏会话保存消息、回复、附件；闲置 30 天删除，可调短接口说明写不保存消息记录，未实测

不强制 schema 的影响不大：审核平台本来就不信任模型输出，结构、枚举、长度、引用逐字匹配都过机械校验，不合格就不形成结论。Experimental 的风险也可控：AI 只是参谋，失败时页面提示「AI 模型尚未接入」，规则核验照常工作。

Nexus 侧

  1. 发布者用专用账号（例如 jiuan-audit-svc）：调用以发布者身份运行、扣发布者的额度。只有 Agent 的创建者能发布它，管理员也不例外。
  2. 一个 Agent，不挂工具：系统提示词只要求「按请求里的任务说明和 JSON Schema 输出，只输出 JSON」。任务说明和 schema 随请求发送，提示词仍由审核平台的代码管理。
  3. 一个发布，只开 A2A，钉住版本和模型。发布者失去模型权限时，网关会回落到默认模型、只发一个警告，所以版本血缘要记下发布编号、版本和模型。
  4. 调用密钥：stage、prod 各一把并设到期日；由用户本人在网页签发后填进 ai-model-api-key，不经对话传递。
  5. 管理员配置：调短 hidden_session_retention_days；配好额度、预算告警和模型单价。

审核平台侧：错误码映射

Nexus 返回含义映射为
401 api_key_required；404 publication_not_found没带密钥；密钥无效、过期，或发布已暂停、删除（统一回 404）AI_AUTH_INVALID
429 rate_limited / too_many_inflight限流、并发已满AI_RATE_LIMIT
429 budget_exceeded发布者额度用尽，发布已自动暂停AI_UNAVAILABLE，提醒管理员恢复
503 gateway_unavailable网关依赖不可用AI_UNAVAILABLE
413 payload_too_large请求体超限AI_REQUEST_INVALID
任务终态 failed本轮失败，如 timeoutAI_UNAVAILABLE
流中断、网络错误AI_NETWORK
不是合法 JSON，或校验不通过AI_INVALID_RESPONSE
本地超时或用户取消同时发 CancelTask，否则 Nexus 上这一轮会跑完并计费AI_CANCELLED

每次调用用新的 contextId，不复用会话，避免 conversation_busy 和跨单据串话。草稿核验只发页面文字、不发附件：附件会复制进 EFS 上的会话工作区，VM 隔离缺口修复前不要这样传正式数据。

7如果坚持「整个平台运行在 Nexus 上」

第一轮列出的 7 项平台能力，v0.3.28 一项都没有补上：应用访客身份、应用数据层、确定性步骤、可靠的定时任务与入站 webhook、行级数据范围、Node 24 运行时、回源 HTTPS 与 Agent API 超时。新增的「自定义资源」以后也许能让 Nexus 在客户的服务器上部署并维护这个平台，但它不是托管路径，本版还关着。建议把这 7 项作为需求提给 Nexus 路线图，落地之前不启动迁移。
